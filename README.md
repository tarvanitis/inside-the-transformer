# Inside the Transformer
### From Attention to Reasoning

If you've ever wondered how a Transformer actually works, and you're interested in the mechanics
rather than the hype, this book is for you.

Born from human curiosity, shaped by inference. A book about Transformers, taken apart from
attention to reasoning, with an on-ramp into every hard idea.

The ideas belong to the pioneers. I just cleared another path.

**Free, and for everyone.**

---

## Read it

You can also read the Markdown directly in this repository. Start with
[`frontmatter/01-preface.md`](frontmatter/01-preface.md).

## Who it is for

You do not need a strong mathematics background. Chapter 2 builds the arithmetic you need from
vectors and dot products upward, and every formula in the book is worked through with real numbers
before it is used. If you can read a little Python, the code chapters will land. If you cannot,
skip them. The conceptual track in
[`frontmatter/03-conceptual-track.md`](frontmatter/03-conceptual-track.md) marks a path through the
book that skips the mathematics without losing the argument.

## Running the code

The two code chapters have standalone, runnable companions in [`code/`](code/). Both train a small
model and generate from it, and both were executed end to end with PyTorch rather than only being
read.

```bash
pip install -r code/requirements.txt
python3 code/ch10_gpt.py          # decoder-only GPT: trains and generates
python3 code/ch11_transformer.py  # encoder-decoder transformer: trains and confirms backprop
```

## Building the PDF

```bash
make pdf        # runs both gates, then builds dist/inside-the-transformer.pdf
make check      # gates only
```

Requirements:

```bash
pip install weasyprint pypdf          # PDF rendering, and merging the cover page
sudo apt install pandoc fonts-texgyre # converter and the serif book fonts
cd tools/math && npm install          # one-time, MathJax for display equations
```

Python 3.10+. `pypdf` is needed because the cover is rendered separately and merged in.

## Figures

Every diagram is a static SVG generated by a script, so the coordinates and the plotted values stay
exact and always match the worked examples in the text.

**Edit the generator, never the SVG.** Then regenerate:

```bash
python3 tools/figures/gen_ch05_figures.py          # writes assets/figures/ch05/*.svg
python3 tools/figures/gen_ch05_figures.py --png    # also renders PNG previews (needs cairosvg)
```

The shared drawing toolkit is [`tools/figures/svgkit.py`](tools/figures/svgkit.py). Generating the
SVGs needs nothing beyond the standard library. `--png` previews need `cairosvg`.

The cover is generated the same way, by [`tools/figures/gen_cover.py`](tools/figures/gen_cover.py),
from a set of attention weights that sum to one. It writes `assets/cover/cover.svg`, and it needs
`Pillow` (it measures glyphs so the arcs land on the right words) plus a Times-metric serif font
such as Liberation Serif:

```bash
pip install pillow
sudo apt install fonts-liberation
```

[`frontmatter/02-about-cover.md`](frontmatter/02-about-cover.md) explains what the picture on the
cover means.

## Tooling

This book's own skill, `technical-book` in `.claude/skills/`, covers authoring and maintenance:
architecture, chapter structure, editorial style, production, and refreshing dated claims.

The two build gates are scripts in `tools/`:

- **`check-prose.py`** is a thin wrapper. It calls the scanner from
  [prose-linter](https://github.com/tarvanitis/ai-prose-tools) when that is installed, and reports
  `PROSE GATE SKIPPED` when it is not, so cloning and building this book requires nothing extra.
- **`check-structure.py`** is this book's own checker: figure and table numbering, captions,
  cross-references, and stale dated claims. It has no dependencies, always runs, and reads
  `book-audit.toml` for this book's conventions. A generalized version of it is published as
  `book-auditor` in the same repository.

## How this book was made

I wrote this book with AI assistance. It would be odd to spend twenty chapters explaining how
language models work while being vague about having used one.

The decisions are mine. I chose how the mathematics should be introduced so that a reader without
much background could follow it, and which idea had to come before which. I picked the worked
examples and checked the arithmetic. I asked for every stage of the Transformer to be explained in
terms of what it is for, not only what it computes, and for the same idea from several angles until
one of them landed. The preface is my own writing, with the grammar corrected. The cover began as a
picture in my head, and I kept at it until it existed. It is drawn by a script from eight attention
weights that sum to one, and every figure in the book is made the same way, generated from exact
coordinates so that no diagram can drift away from the numbers in the text. Then I revised, many
times, over a long stretch.

The model drafted the prose, and a great deal of it. I read it, cut it, corrected it, and sent it
back.

A book about transformers, written with one.
